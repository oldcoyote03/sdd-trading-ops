# Executioner Guide

Use generic placeholders unless the human has explicitly defined the domain and role semantics. The goal of this template is to create a structurally useful draft without inventing domain-specific meanings.

## What is This Role?

This role performs approved actions in the operational system within defined time windows, boundaries, and controls. It acts as the direct execution point for the working plan and escalates deviations promptly.

## Day-to-Day Responsibilities

- Carry out approved actions inside defined windows
- Confirm preconditions and readiness checks before action
- Monitor downstream execution status and respond to exceptions
- Record completed actions and exceptions for audit review

## What You See

- Current queue and next actions
- Operational health and status indicators
- Real-time alerts requiring immediate response
- Action approvals and timing constraints

## Decision Authority

- Execute approved actions: Only within the authorized scope, timing, and policy
- Pause or halt action when a safety or compliance condition is triggered: With escalation path
- Request clarification on ambiguous instructions: Before proceeding outside a defined limit

## When to Escalate

- Trigger condition fails or becomes unclear → escalate to the decision owner
- Safety, compliance, or policy condition breached → escalate immediately
- Capacity or system issue blocks execution → escalate to the relevant support role
