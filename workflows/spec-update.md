# Spec Update

## Steps

1. Choose the specs to update. The human names them, or it's all of them.
2. List the open placeholders and gap flags for those specs.
3. Find relevant KB notes for each one.
4. Draft changes, citing notes or gap flags where they help. Leave a placeholder where nothing supports an answer.
5. Check that the changed specs still agree with each other.
6. **Checkpoint**: show the human the proposed diff with a short rationale for each change.
7. Apply only the approved changes.

## Done When

- [ ] A human has reviewed the proposal
- [ ] The approved changes are applied
- [ ] The knowledge base is unchanged
